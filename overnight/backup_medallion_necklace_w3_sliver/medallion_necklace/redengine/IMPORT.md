# witcher3 static mesh handoff

Requested game version: 5.01. Compatibility with that installed game/tool version is unverified.

Native target: `Choose a compatible native mesh/template in your mod project.`

1. Open the matching Witcher 3 REDkit and your mod depot.
2. In Asset Browser use Import > Mesh and select `meshes/medallion_necklace_LOD0.fbx`.
3. Use an appropriate native `.w2mesh`/material resource and assign the separate source textures in its shader. No native material XML is fabricated.
4. Confirm size, orientation and pivot against an exported game reference. The FBX uses Blender's -Z forward/Y up and explicit unit metadata.
5. Configure native collision and entity/item attachment. Cook/build the mod and test in the target game.

All paths below are relative to the asset root.

| Source LOD | Mesh | Its own base color |

Other LOD files are separately textured alternative mesh targets. Do not combine them as native LODs with one material: independent atlases need separate native material bindings. For a shared-material native LOD chain, reproject to one common atlas in the mod tooling first. Cyberpunk alternatives are each named LOD_1 intentionally; 1/2/4/8 native LOD assembly is not performed.

Collision FBX/GLB files are reference geometry; UCX naming does not create REDengine physics. ORM/MetallicSmoothness maps are not native REDengine materials. Match normal-map channels and any specular/gloss inputs to the chosen native shader; roughness-to-gloss alone does not reconstruct a Witcher material.

This pass supports static props. Clothing, characters, deforming weapons/accessories and vehicles need game-specific rigs, weights, physics and attachment checks. Existing rigged/animated inputs are rejected.

Native .mesh/.w2mesh/.xbm resources, entity files, cooked mods and in-game validation are not generated by this pass. Review the asset's technical/art flags before integration.
